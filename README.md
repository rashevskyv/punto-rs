# punto-rs

> **Це форк** [gmoroz/punto-rs](https://github.com/gmoroz/punto-rs). Що додано:
>
> - автовиправлення для української (пара розкладок `us,ua`);
> - повідомлення українською (`language=uk`);
> - значок у треї: пауза, вимкнення на час, слова-винятки, програми, у яких
>   punto-rs не стежить за введенням;
> - збірка для Windows 10/11.
>
> Оригінальний README російською — в upstream-репозиторії.

*Keyboard layout corrector for Linux/Wayland and Windows: typed `ghbdsn` instead of
`привіт`? Hit a hotkey — the word is retyped in the right layout. A Punto
Switcher / Easy Switcher alternative built on evdev/uinput, based on replaying physical keys between two layouts. Docs below are in Ukrainian.*

Виправлення розкладки вже набраного тексту для Linux/Wayland — заміна Punto
Switcher і Easy Switcher. Набрали `ghbdsn` замість `привіт` і пробіл — слово
саме передруковується в правильній розкладці. `Insert` виправляє слово вручну
і скасовує автовиправлення. Ручне виправлення працює в GNOME і KDE Plasma.

Автовиправлення на пробілі працює лише в KDE Plasma з парою розкладок
`us,ua` (`ua` у типовому варіанті) або `us,ru`: активну розкладку демон дізнається через session D-Bus (`org.kde.keyboard`).
В інших середовищах автовиправлення мовчки вимкнене, гаряча клавіша працює. Слово
виправляється, лише якщо в іншій розкладці воно є в словнику, а на екрані —
ні, і модель літер вважає його помітно правдоподібнішим: хибне виправлення гірше
за пропуск. Слова з цифрами не чіпаються; слова з двох літер виправляються за
списком частих (`jy` -> `он`), одна літера — лише разом із наступним
виправленим словом (`F jy` -> `А он`). На розміченому
наборі (`cli/tests/data/layout_cases.tsv`, відкладена частина) — 0 хибних
виправлень на 360 словах, яких чіпати не можна (звичайні слова, терміни,
код, транслітерація), і 194 з 205 виправлених слів у чужій розкладці.
Слова на кшталт `ща`, `афк`, `tls`, `jq` з живого мовлення не чіпаються: список
винятків — `cli/src/layout/exceptions.txt`, його поповнюють скриптом за корпусом,
а не вручну.

## Як це працює

Демон зберігає не символи, а **скан-коди** натиснутих клавіш. Щоб виправити
розкладку, досить стерти набране, перемкнути розкладку системною
комбінацією і повторно відтворити ті самі фізичні клавіші — система сама
видасть літери іншого алфавіту.

Ключова відмінність від Easy Switcher: поза виправленням клавіатура **не
перехоплюється**. Easy Switcher забирав пристрій собі й повторно випромінював кожне
натискання — через це він губив літери під час швидкого набору. Тут читання пасивне.
Лише на час передруковування демон захоплює клавіатури (`EVIOCGRAB`), щоб
набір не змішався з виправленням, а натиснуте за цей час відтворює одразу
після нього.

Ціна за це — гаряча комбінація потрапляє й до активного застосунку. Щоб
вона не спричиняла побічної дії, її можна прив'язати в налаштуваннях віконного
менеджера або композитора до порожньої команди.

## Встановлення

Готові статичні збірки для `x86_64` публікуються в
[GitHub Releases](https://github.com/rashevskyv/punto-rs/releases). Завантажити
останню збірку для поточної архітектури й перевірити її контрольну суму:

```sh
ARCH="$(uname -m)"
case "$ARCH" in
  x86_64) ;;
  *) echo "Архітектура $ARCH поки не підтримується готовими збірками" >&2; exit 1 ;;
esac

BASE_URL="https://github.com/rashevskyv/punto-rs/releases/latest/download"
curl -fLO "$BASE_URL/punto-rs-linux-$ARCH.tar.gz"
curl -fLO "$BASE_URL/punto-rs-linux-$ARCH.tar.gz.sha256"
sha256sum -c "punto-rs-linux-$ARCH.tar.gz.sha256"
tar -xzf "punto-rs-linux-$ARCH.tar.gz"
cd punto-rs
```

Встановити файли з розпакованого архіву:

```sh
sh scripts/install.sh
~/.local/bin/punto-rs --check-config
~/.local/bin/punto-rs --check-session
systemctl --user daemon-reload
systemctl --user enable --now punto-rs
```

Root не потрібен: демон працює як користувацький сервіс systemd і
запускається разом із `graphical-session.target`. Доступ до `/dev/input/*` і
`/dev/uinput` дає група `input`; якщо користувач до неї не входить, один раз
виконайте `sudo usermod -aG input "$USER"` і перезайдіть у систему. Потрібні
systemd-logind і системна D-Bus. Виправлення дозволене лише в локальній
графічній сесії на `seat0`, що належить тому самому користувачеві: TTY, екран
входу, віддалені сесії та сесії інших користувачів його не отримують.

Файли встановлюються в домашній каталог: бінарний файл у `~/.local/bin/punto-rs`,
конфіг у `~/.config/punto-rs/config.conf` (або `$XDG_CONFIG_HOME`), unit у
`~/.config/systemd/user/punto-rs.service`. Інсталятор зберігає наявний
конфіг, а новий зразок кладе в `config.conf.example`. Сервіс він не запускає
й не перезапускає. Під час оновлення перевірте конфіг командою
`punto-rs --check-config`, потім виконайте `systemctl --user daemon-reload` і
`systemctl --user restart punto-rs`. Щоб відкотитися, встановіть попередній архів і
перезапустіть сервіс у той самий спосіб.

Видалення зі збереженням налаштувань:

```sh
systemctl --user disable --now punto-rs
rm ~/.local/bin/punto-rs ~/.config/systemd/user/punto-rs.service
systemctl --user daemon-reload
```

### Збирання з вихідного коду

Потрібні rustup і компілятор C для vendored libdbus. Код крейта лежить у `cli/`,
версію Rust закріплено в `cli/rust-toolchain.toml`, і rustup підтягує її сам.
Клонуйте форк (гілка `main`) і зберіть:

```sh
git clone -b main https://github.com/rashevskyv/punto-rs.git
cd punto-rs
make install
cd cli && cargo build --release --locked
```

Встановлення з вихідного коду: `sh cli/scripts/install.sh cli/target/release/punto-rs`.

Бінарний файл з'явиться в `cli/target/release/punto-rs`.

Збірка для Windows крос-компіляцією з Linux (Debian/Ubuntu):

```sh
sudo apt install mingw-w64
rustup target add x86_64-pc-windows-gnu
cd cli && cargo build --release --locked --target x86_64-pc-windows-gnu
```

Результат — `cli/target/x86_64-pc-windows-gnu/release/punto-rs.exe`. Архіви
релізу для обох систем збирає `cli/scripts/package_release.sh`.

## Використання

| Дія | Клавіші |
|---|---|
| Автовиправлення слова | пробіл після слова; у Windows ще й `Enter` |
| Виправити останнє слово / скасувати автовиправлення | `Insert` |
| Виправити всю фразу | `Super+Insert` |
| Пауза / відновлення | `Super+Pause` |

Виправлення починається лише після відпускання фізичних клавіш. Гарячу
комбінацію треба натискати без сторонніх клавіш. `Shift+Insert` не
перехоплюється програмою і зберігає свою системну дію.

Буфер скидається на `Enter`, `Tab`, `Shift+Tab`, навігації (стрілки,
`Home`, `Delete`), командах із `Ctrl`/`Alt`/`Super`, системній комбінації зміни
розкладки та клацанні мишею. Додаткові причини скидання: автоповтор клавіші,
під'єднання/від'єднання пристрою, втрата подій evdev, пауза і 30 секунд
без введення.

Набір під час виправлення не перериває його: клавіатури захоплено, натискання
накопичуються й відтворюються після передруковування. Якщо клавіатуру вже захопив інший
процес або клавішу ще натиснуто, виправлення пропускається. Клацання, зміна сесії
чи пристрою переривають передруковування: демон відпускає синтетичні клавіші й
скидає буфер, **уже виконані видалення та натискання не відкочуються**. У разі
помилки запису сервіс завершує роботу після спроби відпустити клавіші; systemd
запускає його знову з порожнім буфером.

Під час блокування, зміни сесії, підготовки до сну та помилок logind виправлення
призупиняється, історія скидається. Старі події з черги не
використовуються в новій сесії. Зміни відстежуються через сигнали D-Bus і
періодичну перевірку; знімок стану logind, старший за дві секунди, не дозволяє введення.
Це залежить від коректної передачі `LockedHint` композитором і не є
гарантією миттєвого виявлення блокування.

Клацання відстежуються тому, що перехід між полями введення мишею інакше не
видно демону: без цього виправлення в новому полі вставило б хвіст із
попереднього. Вимикається параметром `track-mouse=no`.

## Значок у треї

Після запуску в треї з'являється значок з активною розкладкою: `UA` на
синьо-жовтому тлі, `EN` чи `RU` на темному. Сірий значок — punto-rs зараз не
виправляє: увімкнено паузу або активна програма у винятках. Меню значка:

- **Пауза** — те саме, що `pause-hotkey`.
- **Вимкнути на…** — пауза на 15 хвилин, 1 чи 4 години, потім робота
  відновлюється сама.
- **Не виправляти «…»** — додає останнє автоматично виправлене слово до
  винятків у тому вигляді, як воно було на екрані.
- **Додати слово-виняток…** — діалог (`kdialog` або `zenity` у Linux,
  стандартне вікно введення у Windows).
- **Слова-винятки** — список; клацання по слову прибирає його.
- **Не стежити в «програма»** — punto-rs перестає стежити за введенням у
  програмі, яка була активною останньою: не накопичує набране й не виправляє,
  ні сам, ні за гарячою клавішею. **Програми-винятки** — список, клацання
  повертає програму.
- **Запускати разом з Windows** — лише у Windows.
- **Вийти**.

Списки — звичайні текстові файли поруч із конфігом: `exceptions.txt` і
`excluded-apps.txt`, по запису в рядку, `#` — коментар, регістр не важливий.
Пункт «Відкрити файл…» відкриває їх у редакторі, зміни підхоплюються на ходу.
Програма в Linux задається класом вікна KWin (`org.kde.konsole`, `firefox`),
у Windows — ім'ям exe (`Code.exe`). Активне вікно в KDE Plasma демон
дізнається через невеликий скрипт KWin, який завантажує сам; в інших
середовищах Linux винятки програм не працюють, решта меню — так.

Значок вимикається ключем `tray=no`.

## Windows

Збірка для Windows 10/11 (`punto-rs-windows-x86_64.zip` у релізах) — один
`punto-rs.exe` без встановлення. Запустіть його; щоб він стартував разом із
системою, увімкніть «Запускати разом з Windows» у меню значка.

- Конфіг і списки — у `%APPDATA%\punto-rs\`: `config.conf`,
  `exceptions.txt`, `excluded-apps.txt`. Без конфігу діють типові значення.
  Журнал — `%APPDATA%\punto-rs\punto-rs.log`.
- Потрібні рівно дві розкладки: англійська й українська або англійська й
  російська. Активну розкладку й програму демон бере з вікна на передньому
  плані.
- Розкладка перемикається комбінацією `layout-switch`, типово `super+space`
  (Win+Space, працює у Windows 10/11 завжди).
- Пауза типово — `shift+pause`: Win+Pause у Windows відкриває «Про систему».
- `Enter` одразу після слова в чужій розкладці punto-rs притримує: спершу
  виправляє слово, потім натискає `Enter`. Повідомлення йде вже виправленим.
  `Shift+Enter`, `Ctrl+Enter` і `Enter` після пробілу не притримуються. У Linux
  так не можна: evdev читається пасивно, `Enter` уже в програмі.
- Мова `auto` — українська, якщо інтерфейс Windows український або
  встановлено українську розкладку.
- Гарячі клавіші punto-rs (Insert тощо) до програм не доходять: Insert не
  вмикає режим заміни.
- Українська розкладка — стандартна «Українська (розширена)»: ґ на клавіші
  `\`, апостроф на `` ` ``.
- Введення в програмах, запущених від адміністратора, звичайний процес не
  бачить; запустіть punto-rs від адміністратора, якщо це потрібно.
- Збірку для Windows зібрано крос-компіляцією з Linux і перевірено
  автотестами; на живій Windows її ще ніхто не випробовував, тож відгуки
  вітаються.

## Налаштування

Конфіг — `~/.config/punto-rs/config.conf`, формат `ключ=значення`.

| Ключ | Типово | Призначення |
|---|---|---|
| `auto-switch` | `yes` | виправляти слово автоматично на пробілі (KDE Plasma, `us,ua` або `us,ru`) |
| `hotkey` | `insert` | комбінація виправлення останнього слова |
| `phrase-hotkey` | `super+insert` | комбінація виправлення всієї фрази |
| `pause-hotkey` | `super+pause` (Windows: `shift+pause`) | призупинити/відновити роботу з очищенням буфера |
| `layout-switch` | `super+space` | системна комбінація зміни розкладки |
| `key-delay` | `1` | пауза між подіями, 1–100 мс |
| `post-backspace-delay` | `0` | пауза після стирання, 0–2000 мс |
| `switch-delay` | `120` | межа паузи після зміни розкладки, 0–2000 мс; у KDE пауза завершується за сигналом про нову розкладку |
| `devices` | порожньо | клавіатури за назвами; порожньо — автовизначення |
| `max-strokes` | `512` | межа буфера, 1–4096 натискань |
| `track-mouse` | `yes` | скидати буфер за клацанням миші |
| `session-guard` | `yes` | перевіряти локальну сесію через logind |
| `buffer-timeout` | `30000` | скидання після простою, 1000–300000 мс |
| `language` | `auto` | мова повідомлень і меню: `uk`, `ru` або `auto` (за локаллю: `uk*` — українська, інакше російська; у Windows — ще й за українською розкладкою) |
| `tray` | `yes` | значок у треї |

Типово `layout-switch=super+space` — стандартна комбінація GNOME. У KDE
Plasma вкажіть свою комбінацію перемикання розкладки: у 6.6, наприклад,
використовувалася `layout-switch=super+alt+37` (`Meta+Alt+K`, де `37` —
скан-код K). Спершу додайте дві розкладки в налаштуваннях робочого середовища
й перевірте їх перемикання звичайною клавіатурою. Версії середовищ, умови
та результати перевірки наведено у [звіті приймання](cli/docs/release-validation.md).

Клавіші задаються назвою (`insert`, `pause`, `scrolllock`, `capslock`, `menu`,
`rightctrl`, `f1`…`f12` та інші) або скан-кодом з `input-event-codes.h`.
Комбінації записуються через `+`, наприклад `super+insert`. Остання клавіша —
тригер, перед нею допустимі лише модифікатори. Числові коди обмежено
діапазоном 1–255; повторювані клавіші та однакові комбінації заборонено.
Помилкові значення, невідомі й повторювані параметри зупиняють запуск.
Явно заданий через `-c` відсутній файл — помилка. Під час ручного запуску без
`-c` відсутність стандартного файлу вмикає типові налаштування; systemd
перевіряє наявність і коректність файлу перед запуском.

COSMIC 1.0.9 не оновлює `LockedHint` під час блокування екрана. Тому
з увімкненим `session-guard` виправлення в сесіях COSMIC заборонене;
у цьому релізі COSMIC не підтримується. Вимкнення захисту не є
виправленням цієї несумісності.

`session-guard=no` призначений для ізольованих тестових середовищ або систем
без logind: автоматичний захист під час блокування/зміни сесії вимикається.
Пауза гарячою клавішею залишається доступною.

Список пристроїв: `punto-rs --list-devices`.
Скан-коди клавіш: `sudo showkey` або `wev`.

## Тести

```sh
make full-check

# Лише в окремій тестовій VM із запущеним сервісом і стандартним конфігом:
cd cli && cargo build --release --example e2e --locked
sudo target/release/examples/e2e --live-session
```

`make full-check` запускає fmt, Clippy, cargo deny, cargo machete, тести
nextest із порогом покриття, перевірку інсталятора та проєктні гейти.

Наскрізний тест створює віртуальну клавіатуру, друкує на ній слово не в тій
розкладці, натискає гарячу клавішу й перевіряє за вихідним пристроєм демона,
що під час набору той мовчав, а після натискання стер і передрукував саме те, що
потрібно, включно з порядком відпускання всіх клавіш. Події надходять в активне вікно.
Цей приклад не запускається командою `cargo test`: автоматичні тести
перевіряють основний цикл із підміненим пристроєм, помилки запису, скасування,
сесії та конфіг без доступу до клавіатури. Підсумковий текст і реакцію застосунків
перевіряють окремо за [матрицею приймання](cli/docs/release-validation.md).

GitHub Actions на кожен push і pull request запускає форматування, Clippy,
модульні тести та збирає статичні архіви для `x86_64`. Під час push
тегу `vX.Y.Z`, що збігається з версією в `cli/Cargo.toml`, ці архіви та їхні контрольні
суми SHA-256 автоматично додаються до GitHub Release.
Перед створенням тегу підготуйте нотатки `cli/docs/releases/vX.Y.Z.md`:
workflow використовує цей файл як опис релізу.

## Діагностика

```sh
punto-rs --check-config
punto-rs --check-session
systemctl --user status punto-rs
journalctl --user -u punto-rs -f
punto-rs -v   # із зупиненим сервісом
```

Перші літери виходять у старій розкладці — збільште `switch-delay`.
Нічого не відбувається — перевірте стан сесії, паузу та збіг
`layout-switch` із системною комбінацією зміни розкладки.
Другий екземпляр не запускається: блокування міститься в `$XDG_RUNTIME_DIR/punto-rs/daemon.lock`.
Файл залишається після зупинки, але саме блокування звільняє ядро;
видаляти файл для повторного запуску не потрібно.

## Обмеження

- Розкладка перемикається інжектуванням системної комбінації, тому її треба
  налаштувати в самій системі, і вона має перемикати рівно між двома розкладками.
- Підтримувана модель — один друкований символ на натискання основного блока
  клавіатури, дві розкладки без IME, Compose і dead keys. AltGr і автоповтор
  скидають буфер; розкладки з такими механізмами потребують окремих перевірок.
- Демон не бачить тексту на екрані: якщо редагувати курсором посеред рядка,
  буфер і екран розійдуться. Такі випадки гасяться скиданням буфера на навігації
  та на клацанні мишею.
- Дотик до тачпада замість фізичного клацання не видно на рівні evdev — його
  синтезує вже libinput. Буфер скине лише справжнє натискання тачпада
  або кнопки миші.
- Поля паролів, автозаміни та зміну тексту самим застосунком демон не
  знає. Перед чутливим введенням вмикайте паузу або додайте програму
  (менеджер паролів, термінал) до винятків через значок у треї.
- Передруковування не атомарне щодо фізичного введення та зміни фокуса.
  Скасування обмежує подальше інжектування, але не відновлює початковий текст.
